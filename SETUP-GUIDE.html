Copy Portal — Complete Setup Guide

Vercel + Supabase + Google Cloud · ~30 min · all free tiers

1. Supabase 2. Google Cloud 3. Enable Google 4. config.js 5. Vercel 6. Test

Follow these steps in order. Each phase names the exact buttons to click and the exact values to paste. You only need the free tier of all three services.

Phase 1
Create Supabase project + table
Phase 2
Create Google OAuth credentials
Phase 5
Deploy to Vercel
1

Supabase — create project & get keys

  1. Go to supabase.com and Sign in (Google/GitHub auth).
  2. Click New project.
  3. Fill in:
    • Organization: create one if needed (click "New organization").
    • Project name: copy-portal
    • Database password: click "Generate a password" and save it (shown once).
    • Region: pick closest to your users — for India use Singapore (ap-southeast-1) or Mumbai (ap-south-1).
  4. Click Create new project → wait 2–3 minutes until status is green.
  5. Open Project Settings → API (gear icon, left sidebar).
  6. Copy two values somewhere safe:
    • Project URL — like https://abcdefghijkl.supabase.co
    • anon public key — the long eyJ... string

    The service_role / JWT secret keys stay secret — never put them in the app.

  7. Create the table: SQL Editor → New query → paste supabase/schema.sql → click Run.
  8. You should see "Success. No rows returned". Verify under Table Editor → snippets (empty table exists).
2

Google Cloud — create OAuth credentials

  1. Go to console.cloud.google.com and sign in.
  2. No project yet? Top bar → Select a project → New Project → name copy-portal → Create.
  3. Select that project in the top bar — everything below runs inside it.
  4. APIs & Services → OAuth consent screen:
    • User type: External → Create.
    • Fill only required fields (App name, support email, developer contact email).
    • Add your own Google account under Test users (recommended).
    • Save — no scopes or publishing needed.
  5. APIs & Services → Credentials → + Create credentials → OAuth client ID:
    • Application type: Web application.
    • Name: copy-portal-web.
    • Authorized JavaScript origins (add both): 
      https://<your-project-ref>.supabase.co
http://localhost:3000
    • Authorized redirect URIs (add both): 
      https://<your-project-ref>.supabase.co/auth/v1/callback
http://localhost:3000
    • Click Create.
  6. Copy the Client ID and Client Secret now (viewable later from the credentials list).
What is "your-project-ref"?

It's the subdomain portion of your Supabase Project URL. If your URL is https://abcdefghijkl.supabase.co, then abcdefghijkl is your project ref.

3

Supabase — enable Google login

  1. Back in Supabase: Authentication → Providers.
  2. Find Google → toggle Enable Sign in with Google ON.
  3. Paste Client ID and Client Secret from Phase 2 step 6.
  4. Optionally enable Skip non-verified users to let anyone with a Google account in.
  5. Click Save.
  6. Authentication → URL Configuration:
    • Site URL: your future Vercel URL, e.g. https://copy-portal.vercel.app (update in Phase 5 once it exists).
    • Redirect URLs — add both: 
      http://localhost:3000
https://copy-portal.vercel.app
    • Click Save.

You've now created the two "loop" links: Google Cloud redirect → Supabase callback, then Supabase redirect → your app domain.

4

Put your keys in config.js

Edit config.js in this project:

window.SUPABASE_CONFIG = {
  url: "https://abcdefghijkl.supabase.co",   // Supabase Project URL (Phase 1)
  anonKey: "eyJhbGciOi...",                 // Supabase anon public key (Phase 1)
  redirectTo: "https://copy-portal.vercel.app" // or http://localhost:3000 while testing
};
  • redirectTo must match one of the Redirect URLs you added in Phase 3.
  • The anon key is public by design — RLS protects the data, not the key.
5

Vercel — deploy

Option A — via GitHub (recommended)

cd copy
git init
git add .
git commit -m "Copy Portal with Supabase auth"
git branch -M main
git remote add origin https://github.com/YOUR_USER/copy-portal.git
git push -u origin main
  1. Go to vercel.com → sign in with GitHub.
  2. Add New → Project → import the copy-portal repo.
  3. Configure:
    • Framework preset: Other.
    • Root directory: the folder holding index.html.
    • Build command: empty. Output directory: empty.
    • Vercel auto-detects vercel.json (static files).
  4. Click Deploy → wait ~30 seconds → get your URL https://copy-portal.vercel.app.
  5. Now fix the two URL lists with the real domain:
    • Google Cloud → Credentials → OAuth client → replace/add https://copy-portal.vercel.app to JS origins + redirect URIs.
    • Supabase → Auth → URL Configuration → add it to Site URL + Redirect URLs.
  6. Optional: add a custom domain (e.g. clip.example.in) in Vercel → Project → Settings — then add that https URL to both redirect lists too.

Option B — CLI (no GitHub)

npm i -g vercel
cd copy
vercel --prod

Follow the prompts (login, link directory, root = the copy folder).

6

Test the full flow

  1. Open your Vercel URL in an incognito window → you see the Continue with Google card.
  2. Click it → choose a Google account → you land back, logged in.
  3. Click + New, create a snippet, refresh → still there (stored in Supabase, not localStorage).
  4. Open a second browser → sign in with a different Google account → first account's snippets are invisible (RLS working).
  5. Test Sign out (top-right icon), edit, delete, favorite, search, tags, folders.

Troubleshooting

Problem Likely cause Fix
redirect_uri_mismatch from Google Google redirect URI doesn't include the Supabase callback Verify https://<ref>.supabase.co/auth/v1/callback is in Google Cloud → OAuth client → Authorized redirect URIs
Blank / localhost page after OAuth redirectTo in config.js doesn't match a Supabase Redirect URL Update config.js + Supabase Site URL and Redirect URLs
401 on app load / "No rows returned" Wrong keys in config.js, or schema.sql not run Re-run Phase 1 step 7; check Project URL + anon key in Phase 4
Login button error in console Google provider disabled, or wrong Client ID / Secret Check Supabase → Auth → Providers → Google settings
Data missing after switching browser Signed into a different Google account Sign out/in with the account that owns the data
Login loop / stuck Supabase Site URL points to an old domain Update Auth → URL Configuration → Site URL to current Vercel URL

Security notes

  • anonKey is public by design — never put the service_role key in the frontend (it bypasses RLS).
  • All schema.sql policies scope rows to auth.uid() — keep RLS enabled.
  • If a test fails, open the browser console (F12) for the exact error message before debugging.
